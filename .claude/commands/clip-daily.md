Unattended daily clipping run, started by a scheduled task. **Do not ask the user anything**: use saved preferences and decide everything yourself. Run from the clipping-gta-6 project root. If `$ARGUMENTS` or `CLIPPER_PROFILE` names a profile (a folder in `profiles/`), pass `--profile <name>` to every `python3 -m clipper` command; the default is `gta6`. If the arguments include `live` (the every-2-hours live run that `clipper schedule live` installs), do only step 0 and then step 5's report: skip step 1 and the new uploads. Read `research/viral-gta-shorts.md` first. **Permissions:** this run can only use pre-approved tools, so run every `python3 -m clipper`, `ffmpeg` or `ffprobe` command on its own: no `cd` (you're already in the project root), `&&`, `;`, pipes or redirects, and no `ls`/`cat`/`head`. Read files with the Read tool and find them with Glob/Grep. Anything else is refused without asking.

0. Live chunks first: `python3 -m clipper live jobs` lists recorded live-stream chunks not clipped yet (recorded by the stream watcher that `python3 -m clipper schedule live` runs every 5 minutes for the streams in the profile's `live.yaml`). A chunk still transcribing has no `candidates.md` yet: leave it for the next run. For each, run `python3 -m clipper analyze <job>`, then do steps 2–4 for it, then `python3 -m clipper live done <job>` (the recording stays a few hours so other streams' multi-streamer edits can still use it, then the cleanup deletes it).
1. `python3 -m clipper daily`. It reads `prefs.yaml`, finds the newest unprocessed GTA 6 uploads from the profile's `creators.yaml` (`sources_per_day` of them, first `daily_max_minutes` of long streams), downloads and analyzes them, and prints JSON. If `analyzed` is empty, write "No new uploads today" to `exports/<profile>/<date>/index.md` and stop.
2. Choose how many videos to make: if `videos_per_run` is `auto`, use `videos_to_export` from the JSON (each source's recommended count, from tiered volume jumps, peaks, hype words and most-replayed, capped by `max_videos_per_run`), so longer, livelier sources give more clips. Drop any pick you judge weak. Otherwise use the number. Read each `candidates.md`, view the contact sheets, and check word timings in `transcript.json` (one word per line: Grep for `"s": 843.` to find second 843, then Read around it). Apply the research rules: cold open on the reaction or setup line, the moment pays off an open question, 9–25s for reactions, standalone.
3. For each source, write `jobs/<id>/picks.json` exactly as `/clip` step 7 describes, keeping the hooks `python3 -m clipper simulate jobs/<id>/picks.json` lists on its `keep` line (`hooks_per_video`, or the data-chosen count when `auto`). Set `clip_type` per moment and follow its row in the research Playbook (hook order, styles, voiceover, length). Every hook must open a loop. Draft at least 3 different hook types per clip before simulating (as `/clip` step 7 says), and note in the report any clip that kept fewer and why. Across the run, vary the hook wording as `/clip` step 7 says: no two videos open their hooks or titles with the same words, and spread the leading hook types. Story cuts and multi-streamer edits (`segments`, `clipper find`) are welcome next to single clips, as `/clip` step 7 describes; never reuse footage already exported. Run `python3 -m clipper check jobs/<id>/picks.json --job <id>` and fix everything it flags before rendering. Voiceover per `voice`: `off` none, `all` every video, `auto` only where the research says it helps. If a facecam is visible, use `python3 -m clipper frame` for a split layout.
4. Render each source with `python3 -m clipper render <id> --picks jobs/<id>/picks.json`. If it exits with code 3 (no Fish Audio key), re-run with `--allow-say` and note in the report that the voiceover used the built-in macOS voice because no Fish key is saved (run `/clip` or `python3 -m clipper voice-setup` once to add one).
5. Spot-check one frame per video with ffmpeg. Then append a short report to `exports/<profile>/<date>/index.md`: source videos, chosen moments with source links, and anything skipped and why. Your final message is the same short report.
