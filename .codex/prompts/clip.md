---
description: Find the best GTA 6 moments in a YouTube video and render captioned vertical shorts with hook and title variants
argument-hint: [youtube-url | search phrase]
---

Find, review and render GTA 6 short-form clips with the local `clipper` CLI (run from the clipping-gta-6 project root). Everything runs locally (FFmpeg, yt-dlp, whisper.cpp, Demucs, WhisperKit). Read `research/viral-gta-shorts.md` before step 4; every hook, title, font and voiceover choice must follow it.

Input: $ARGUMENTS (a YouTube URL/id, a search phrase, or empty to scan the creators list).

1. **Setup questions.** Run `python3 -m clipper prefs show` for the saved defaults, then ask these in one go, with the saved value pre-selected or recommended. Ask with multiple-choice questions: in Claude Code use the AskUserQuestion tool; in Codex use request_user_input if available (Plan mode), otherwise list numbered options and wait for the reply.
   - **AI voiceover?** "No voiceover" / "Every video" / "Let the agent decide per video" (recommended: per the research, reactions skip it and context-less clips get one).
   - **How many finished videos?** "As many as are worth taking" (recommended: the analysis scores each source and recommends a count, so a 50-minute stream yields more than a 20-minute one) / 1 / 3 / 5.
   - **Hook variations per video?** "Let the data decide" (recommended: `auto` uses the count with the best breakout chance in `clipper simulate --strategies`, currently 3) / 2 / 3 / 4 / 5 (one MP4 per hook).
   - **Save these as defaults for scheduled runs?** Yes / No.
   If they choose to save, run `python3 -m clipper prefs set voice=<off|all|auto> videos_per_run=<auto|n> hooks_per_video=<auto|n>`.
2. **Find a GTA 6 video.** With no URL, run `python3 -m clipper watch` (add `--search "<phrase>"` for a phrase). It keeps only videos whose title, description or tags prove they are about GTA 6. Show a table (channel, title, length, id, evidence, processed) and ask which one to clip.
3. **Fetch + analyze.** `python3 -m clipper run <url-or-id>` (for streams over ~2h add `--section H:MM:SS-H:MM:SS`). This writes `jobs/<id>/candidates.md` plus contact sheets.
4. **Review like a viral editor.** Read `candidates.md`: its header says how many videos are worth exporting and whether the source is a reaction or info video. Each candidate has a tier (strong / maybe / skip) based on the signals the 500k+ Shorts shared: sudden volume jumps (screams, reactions), loudness peaks, hype words, sound events and most-replayed data. View each `review/cand_NN.jpg` and read the word timings in `transcript.json` around the best moments. Re-rank by the research: start ON the reaction or the setup line (cold open); the moment must pay off a question a viewer would have; works without context. For every moment, name its **click trigger** from the research "Outlier study": a curiosity gap, the viewer as judge, play-along/streak, suspense (we know more than the target), irony against the persona, a shock confession, status/celebrity, or an absurd one-line premise. No nameable trigger, no clip. The premise must land in the first second, and the clip should end on the face. Hook and title state the situation and withhold the outcome. Also read the **Scenario candidates** section and hunt for **curiosity gaps** anywhere in the transcript: the streamer makes, finds, tries or shows something new (a combo, trick, secret spot, custom car or room, build, first try, a real-life thing recreated in the game) and the outcome stays unknown until a reveal or a face. They often have no volume spike, so judge them from the transcript and contact sheet (research "Scenario case study"). Their hooks name the new thing and withhold what it is ("What new *combo* did Kai just invent?"). **Length is your call per moment**, from the analysis (the `candidates.md` aim, the clip_type's playbook length) and where the payoff actually lands: any length up to **60s maximum**, as short as the moment allows, as long as the payoff needs. Only take a moment that is worth posting. With "as many as worth taking", export the recommended count, minus any you judge weak, plus a skip-tier moment only if you can say why it works. Present the picks as a table (rank, source timestamp + link, length, format, voiceover yes/no + why, why it works) and ask the user to approve, trim or swap.
5. **Voiceover key (only if any approved video has a voiceover).** Run `python3 -m clipper voice-setup` with a 10-minute timeout. It checks any saved key; otherwise it opens the Fish Audio API-key page (free developer tier) and a temporary TextEdit note. Tell the user: "Click Get your API key, paste it into the TextEdit note, and press Cmd+S." The command verifies the key, saves it to `.env`, and deletes the note. Never print the key. If they'd rather not, drop the voiceovers.
6. **Choose a layout.** If a facecam is visible, run `python3 -m clipper frame <id> <seconds>`, read the gridded frame, and use `"layout": {"type": "split", "face": [x, y, w, h]}` (fractions). Otherwise use `{"type": "fit"}`.
7. **Write picks.** Save `jobs/<id>/picks.json`, a list with one entry per video:
   `{"start", "end", "clip_type", "layout", "hook_style", "caption_style", "hooks": [N hooks], "titles": [4 titles], "description", "hashtags", "voiceover" (only if chosen), "labels" (optional)}`.
   - **Three kinds of video, all welcome** (YouTube's originality rules favour edited videos over raw re-uploads; research "Originality"):
     - **Single clip** (`start`/`end`): one moment, as above. Still the default when one moment carries itself.
     - **Story cut**: several moments of one stream in one Short (setup → turn → payoff, e.g. "Moment of truth" → the blackout → "y'all missed that entire thing?"). Use `"segments": [{"start", "end"}, ...]` (source seconds, in play order) instead of `start`/`end`. Cut dead air between beats; every segment must earn its seconds.
     - **Multi-streamer edit**: the same moment from several streams (same cutscene, same heist, same reveal). Run `python3 -m clipper find "<a line said in it>"` (searches every stream recorded or fetched in the last 6 h; `--hours N`): GTA cutscene dialogue is identical in every stream, so one line finds the same moment everywhere, with each job's source seconds. Add `"job": "<that job>"` (and its own `"layout"` if its facecam sits elsewhere: `clipper frame <that job> <s>`) to the segments from other streams. Every source is credited in the description.
     - The **60s maximum** counts all segments together. A segment pick's `labels` use seconds of the finished clip (0 = its first frame).
   - **Never reuse footage:** don't pick a moment (or segment) already used by an exported clip; the same footage gets no reach the second time. `clipper check --job <id>` fails any pick that shares more than 3 s with a clip this profile already exported.
   - **labels (action captions):** for quiet stretches where nobody talks, timed captions that say what's happening, the way the biggest Kai Cenat Live Shorts do (`*ENTERS*`, `*GETS CLOSER*`, `*NOTICES*`, `*TRIES*`, `*AURA*`): `[{"s": <source seconds>, "e": <source seconds>, "text": "*GETS CLOSER*"}]`. Use 1–3 words, present tense, in asterisks, and build tension toward the payoff. They're dropped wherever someone speaks.
   - **clip_type first:** `reaction`, `comedy`, `news`, `gameplay`, `showcase` or `scenario`, decided per *moment* (`candidates.md` suggests one per source, and the research "Playbook" table defines them). It sets the hook structures in order, hook_style, caption_style, the voiceover default and the length. Example: xQc's hostages singing harmonies is `comedy` (meme box, relatable/tease hooks), not a reaction.
   - **hooks:** the chosen number, each a **different** structure, best first by measured effect on 3,481 gaming Shorts (`python3 -m clipper simulate` prints the table): number promise 2.5x, shock fact 1.7x, relatable situation 1.5x, withheld/negation 1.4x, question 1.2x, tease 1.2x (only when it says what to watch), superlative 1.1x. Naming the streamer adds 1.2x ("Nobody expected xQc's hostages to *SING*"). Never use: vague hooks with one content word ("Wait for the harmony...", 0.67x), bare topic labels (0.88x), announcement wording (0.85x). First-person claims (0.94x) and a CAPS word with no other structure (0.97x) don't help. Never spoil the clip ("… Reaction"). 2–6 words (relatable up to 9), one keyword marked `*like this*`. Each hook becomes a file name, so keep them distinct.
   - **hook_style:** `bold` (Montserrat Black, news/gameplay), `box` (TikTok Sans meme box, skits), `label` (creator series) or `none`.
   - **caption_style:** `boxed` (Bebas on black) for streamer reactions, `bold` for commentary/news, `comic` for playful gameplay.
   - **Choosing hooks:** draft one hook for every type that honestly fits the clip_type (research "Title formulas" table; never invent a number or a list the clip doesn't have), run `python3 -m clipper simulate jobs/<id>/picks.json`, and keep the hooks on its `keep` line (it uses `hooks_per_video`, or the data-chosen count when that is `auto`), each a different type, best first. Don't give every clip every type: forcing misfits lost in every simulated scenario. But draft every type that fits, at least 3, before simulating (the playbook row for its clip_type lists 4 in order; a reaction almost always fits relatable, withheld/negation and question), so `keep` can fill `hooks_per_video`. Fewer than 3 only when you can name why the others don't fit, and say so in the picks table.
   - **titles:** one per hook, same order, same hook type, built from that type's formula in the research "Title formulas" table (real titles from the 3,481-Short dataset). The title goes with that hook's MP4. Max 100 characters, 1–2 CAPS words, include "GTA 6"/"GTA VI" (a joke title may skip it if #gta6 is in the hashtags).
   - **Start time:** `candidates.md` shows each candidate's opening line type. The viral clips opened in-scene, on action, a claim, a question or a number promise, never on filler. If it says filler, move `start` to the first strong line.
   - **Name anchor:** for a well-known streamer, make at least one hook a premise with their name and one CAPS twist word ("xQc forces the hostages to *SING*"); fans stop on the name.
   - **Vary the wording across videos:** when you make several videos, no two hooks or titles may open with the same words ("Kai was NOT ready for…" on every clip reads as templated), and where two hook types fit a clip about equally well, lead with one the other videos aren't leading with. A feed that repeats one formula gets swiped.
   - Then run `python3 -m clipper check jobs/<id>/picks.json --job <id>`. Then `python3 -m clipper simulate jobs/<id>/picks.json` and put the top-ranked hook first. Fix every **fail**; **notes** are judgment calls you may keep if you can say why.
   - **voiceover:** one line of 10 words or fewer, following the research's "When to add an AI voiceover".
8. **Render.** `python3 -m clipper render <id> --picks jobs/<id>/picks.json`. Output goes to `exports/<profile>/<date>/video N/` (`gta6` unless you passed `--profile`) (numbering continues across runs): one MP4 per hook, named after the hook, plus `titles and description.md`; `exports/<profile>/<date>/index.md` lists them all. Exit code 3 means the voiceover key is missing: go back to step 5. Extract a frame or two with ffmpeg and look at them before delivering.
9. **Deliver.** List each new `video N` folder with its hook files, the titles, the description and the source link. Open `exports/<profile>/<date>` (`open` on macOS, `xdg-open` on Linux; skip on a headless machine). Suggest A/B testing the hooks, and remind the user to only post clips they have rights or creator permission to use. Mention `/clip-creators` to change who's watched and `/clip-schedule` to run this daily.
